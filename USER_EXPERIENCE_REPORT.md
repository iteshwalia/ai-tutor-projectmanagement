# PM Mentor User Experience Report

**Report date:** 28 November 2026
**Project:** PM Mentor — AI Project Management Tutor

Word edition: [USER_EXPERIENCE_REPORT.docx](USER_EXPERIENCE_REPORT.docx)

## Executive summary

PM Mentor supports working professionals through a focused learning loop:

**Choose a topic and difficulty → learn or practice → receive feedback → review progress → continue.**

Learners can use Learn, Practice, Quiz, and Challenge modes. Practice and quiz questions are generated by the configured model on each question request; when no model key is configured, the application uses its built-in topic- and difficulty-matched question bank.

After an answer, the learner sees correctness, an explanation, personalized guidance based on their profile and topic progress, and a topic-specific best practice. The current automated suite passed 30 tests. No formal learner interviews or usability study are documented, so this report describes the implemented experience and tested behavior rather than measured learner outcomes.

## Intended learner and learning context

| Consideration | Product response |
|---|---|
| Learner | Working professionals building project-management knowledge |
| Learning context | Short, self-paced sessions |
| Subject scope | Planning and scheduling, Agile, stakeholders, risk, leadership, and AI project management |
| Learner context | Name, current level, focus topic, and preferred difficulty |
| Desired result | Understand a concept, apply it, learn from mistakes, and identify a next step |

## Current experience

### Choose a learning activity

The interface offers four modes: Learn for explanations, Practice for confidence-building questions, Quiz for knowledge checks, and Challenge for applied scenarios. A chat composer remains available for learner-directed questions.

### Personalize the activity

Learners can select a focus topic and difficulty. Question requests use the saved topic and difficulty, while the tutor can use the configured model provider to generate fresh practice and quiz questions. Without a provider key, the authored question bank keeps these modes available.

### Learn from each answer

Correct and incorrect responses receive an explanation. Incorrect responses also show a hint and the correct answer. Personalized feedback uses the learner's name, difficulty, and topic accuracy to suggest a next reasoning step. A separate best-practice tip gives an actionable recommendation specific to the topic.

### Review progress

Attempts, correct answers, accuracy, and per-topic results update after each answer. The progress summary highlights stronger and weaker topics, suggests a next lesson, and can be downloaded as a report.

## Design rationale

1. **Keep the tutor focused:** Project-management topics, examples, and learning modes set clear expectations.
2. **Support different study intentions:** Learners can explore, practice, self-check, or apply concepts.
3. **Make personalization visible:** Topic and difficulty shape questions and response guidance.
4. **Make mistakes useful:** Hints, explanations, personalized next steps, and practical tips make an incorrect response actionable.
5. **Keep learning available without credentials:** Built-in demo content and the authored question bank provide a no-key path.
6. **Make progress reviewable:** Topic-level metrics and a downloadable report help learners choose what to study next.

## Validation evidence

- **30 automated tests passed:** 26 backend/API tests and 4 Playwright browser tests.
- Browser tests cover profile recovery, mode prompts, quiz/practice answering, personalized-feedback and best-practice labels, progress, report download, and reset.
- Manual visual checks used a local isolated app at desktop (875 × 674) and mobile (390 × 844) viewport sizes. The mobile document width matched the viewport, and the chat content remained vertically scrollable.
- Test details and responsive observations are in [REGRESSION_TEST_REPORT.md](REGRESSION_TEST_REPORT.md) and [VISUAL_TEST_REPORT.md](VISUAL_TEST_REPORT.md).

## Resolved usability finding

The fallback question bank displays choices labeled A–D. Previously, submitting only a correct choice letter could be marked incorrect. Evaluation now maps letters A–D (case-insensitive, with an optional period) to their displayed choices. The UI regression test submits a lowercase letter with a period and confirms the correct-answer flow.

## Constraints and next validation

- No formal usability study, learner interviews, or measured learning-outcome evaluation is documented.
- Automated browser testing uses Chromium and demo mode; external model calls are mocked in API tests.
- The visual review was not a pixel-diff, full accessibility audit, or cross-browser compatibility test.
- Follow-up usability work should test answer-entry expectations, keyboard/screen-reader journeys, and the clarity of feedback with working professionals.
